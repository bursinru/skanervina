# Эксперименты обучения

## План первого этапа

1. Зафиксировать состояние сервиса до обучения и не смешивать неопределённость с ошибкой распознавания.
2. Сформировать воспроизводимый manifest из карточек и существующих векторов SigLIP 2. Не использовать `eval/queries` без разметки.
3. Исключить неоднозначные пары с одинаковыми файлами. Разделить вина по хешу исходного изображения до генерации искажений.
4. Сгенерировать по два синтетических запроса: перспектива, поворот, небольшой crop, свет, оттенок, шум, размытие, JPEG и блик. Это приближение условий камеры; полноценные снимки полки оно не заменяет.
5. Обучить residual query adapter, оставив encoder SigLIP 2 и галерею неизменными. Использовать все эталоны обучающей части как отрицательные примеры, включая визуально близкие вина.
6. Выбрать эпоху только по validation MRR, затем один раз оценить held-out test. Сравнить с необученным SigLIP на тех же запросах и галерее.
7. Подобрать экспериментальные пороги только по validation, оценить их на test, сохранить доверительный интервал разницы Top-1 с группировкой по вину.
8. Не включать обученную модель в сервис без проверки на размеченных реальных снимках.

## Что фиксируется

- Top-1 / Top-3 / Top-5: доля запросов, где правильный slug попал в первые 1/3/5 результатов.
- MRR: среднее обратное место правильного результата; выше лучше.
- Coverage: доля запросов, принятых автоматически по similarity и отрыву от второго кандидата.
- Accepted precision и false accepts: точность принятых ответов и количество ошибочных уверенных ответов. При нуле принятых ответов precision равна null, а не 100%.
- Размеры выборок, дубликаты, seed, SHA-256 manifest и исходников, версия модели, число обучаемых параметров, loss по эпохам и длительность.

Все показатели обучения относятся к **синтетическим фото**, не являются оценкой точности на новых реальных этикетках. Известные эталонные фото всех вин находятся в галерее — это нормальный режим поиска. Но wine identities из validation/test не участвуют в обновлении весов, даже как отрицательные примеры. Близкие по содержанию, но не идентичные байт-в-байт изображения могут оставаться в разных частях.

## Запуск

Нужны установленное `backend/.venv-cv`, работающая PostgreSQL и подготовленный индекс (см. `backend/README.md`). Из корня проекта:

```sh
HF_HUB_OFFLINE=1 PYTHONPATH=backend backend/.venv-cv/bin/python -m training.run \
  --run backend/data/training/adapter-v1
PYTHONPATH=backend backend/.venv-cv/bin/python -m training.calibrate \
  --run backend/data/training/adapter-v1
```

Первый эксперимент: 256 обучающих вин, 64 validation, 64 test; по два варианта каждого фото. 20 эпох, AdamW, lr=0.001, seed=20260916. SigLIP frozen; обучается только слой коррекции запроса из 197504 параметров. Новые запуски получают новый каталог `--run`; завершённый запуск не перезаписывается. Извлечение векторов возобновляется с последнего сохранённого batch; если остановить обучение, оно повторяется с первой эпохи с тем же seed. `last.pt` дополнительно содержит optimizer и RNG для дальнейшей реализации точного resume обучения.

## Артефакты

В `backend/data/training/<run>/` (исключено из Git): `config.json`, `manifest.json`, `status.json`, `queries.npz`, `gallery.npy`, `history.json`, `best.pt`, `last.pt`, `metrics.json`, `calibration.json`. Вес модели и исходные данные не публикуются. Сводные метрики копируются в эту папку `reports/training/`, чтобы сохранить их вместе с кодом.

Исходные цифры: [baseline-2026-09-16.json](baseline-2026-09-16.json).
