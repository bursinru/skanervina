# Состояние на 17.09.2026

## Реализовано

- Nuxt → FastAPI → PostgreSQL/pgvector; 2103 карточки, 2036 изображений в индексе.
- Одна карточка при matched/uncertain; сомнительный результат помечен. При unknown карточки нет. Eval API сохраняет null для uncertain.
- Административная диагностика: `/scanner?admin=1`, ключ SCANNER_ADMIN_TOKEN из backend/.env.local. Процент сходства, время visual/OCR/total и ожидание в браузере. Без ключа API скрывает показатели; неверный ключ возвращает 403.
- Автоматическое выделение центральной панели этикетки на backend с защитным отступом; ручного crop в интерфейсе больше нет. Анимация показывает исходное фото, отправленное в поиск.
- CPU-подготовка изображений оптимизирована без изменения входа SigLIP: на трёх фото максимальная разница pixel_values равна 0. OCR уменьшен до 1000 px; короткий текстовый шум не считается доказательством совпадения.

## Новый benchmark: 3 image + 3 OCR + 1 combined

Apple M1, `CV_DEVICE=cpu`, 4 потока, 3 последовательных повтора каждого режима. Latency — медиана по трём фото; p95 здесь ориентировочный из-за малого набора. Время включает HTTP, но не загрузку модели до старта API.

| Режим | Query median / p95 | Query unknown | Reference Top-1 |
|---|---:|---:|---:|
| Image · весь кадр | 0.449 / 0.636 с | 0% | 3/3 = 100% |
| Image · авто-crop | 0.432 / 0.523 с | 0% | 2/3 = 66.7% |
| Image · авто-crop + enhancement | 0.424 / 0.539 с | 0% | 2/3 = 66.7% |
| OCR · весь кадр | 1.016 / 1.097 с | 66.7% | 0/3 |
| OCR · авто-crop | 0.771 / 0.806 с | 33.3% | 0/3 |
| OCR · авто-crop + enhancement | 0.775 / 0.849 с | 33.3% | 0/3 |
| Combined · авто-crop image + OCR | 0.925 / 3.405 с | 0% | 2/3 = 66.7% |

IoU автоматического crop на трёх evaluation-only разметках: **0.808 в среднем**. Вывод по текущим данным: auto-crop уменьшает размер рабочей области, но не гарантирует лучшую image accuracy; OCR на этих снимках остаётся слабым сигналом. На reference-фото у OCR-auto Top‑3 = 66,7% при Top‑1 = 0% — это полезно для reranking, но недостаточно для самостоятельного ответа. В combined есть заметные CPU-всплески visual inference, поэтому p95 важнее одной удачной медианы. Контрольный набор из трёх reference-фото показывает, что full-frame сейчас точнее авто-crop, поэтому результат combined остаётся `uncertain` при недостаточном разделении кандидатов. Это не общая accuracy: на трёх query-фото правильные slug организатором скрыты.

Полный JSON с результатом каждого повтора: [benchmark-modes.json](benchmark-modes.json). Исторические замеры до автоматического crop: [cpu-label-ocr-optimized.json](cpu-label-ocr-optimized.json), [начальный прогон](cpu-label-ocr.json), [идентичность подготовки SigLIP](preprocessing-equivalence.json), [проверка каталога](catalog-coverage.json).

## Качество и проверки

- 22 backend-теста прошли; Nuxt production build, JS syntax и git diff --check прошли.
- Контрольный поиск исходных изображений каталога: 3/3. Это проверка индекса, не точность на новых фото.
- На трёх реальных фото отдельно проверены три image-режима, три OCR-режима и combined. Официальные правильные slug скрыты; accuracy для query не заявляем.
- На фото Массандры белый Мускатель путается с другими винами линейки. Ответ остаётся uncertain. Автоматический crop не гарантирует улучшения точности.
- В каталоге не найдены название Donum/Донум и Пино Нуар у Табии; нужно сверить и дополнить исходные данные.
- OCR на декоративных этикетках ошибается. Сходство изображений и текстовый score не являются вероятностью правильного ответа.
- В браузере проверено: загрузка → автоматическое выделение на backend → поиск → одна карточка с предупреждением.
- Живой API через Nuxt: профиль в PostgreSQL, изоляция, валидация и распознавание проверены. Результаты: backend/data/verification-top1.json.
- Экспериментальный обученный адаптер не включён в рабочий поиск; предыдущие результаты — в reports/training/.

## Продолжение и перенос

Обычный CPU-сервер подходит: Linux + Docker Compose + HTTPS. Начальная конфигурация для небольшой нагрузки — 4 vCPU, 8 GB RAM, 40 GB SSD; это запас для старта, не измеренный минимум и не гарантия скорости M1. Docker на этой машине не запускался; проверен нативный CPU-инференс.

Перенести исходники, отдельный Датасет, дамп PostgreSQL с векторами или повторно построить индекс, веса модели и настройки. Модели занимают около 1.4 GB, фотографии каталога — 2.1 GB. Иллюстрации карточек пока используют исходный CDN.

Дальше: дополнить отсутствующие карточки/67 изображений, собрать реальные размеченные фото, проверить и дообучить адаптер, откалибровать пороги и улучшить OCR. Матрица режимов и новые замеры находятся в [benchmark-modes.json](benchmark-modes.json); для пользовательских query-фото ground truth не опубликован, поэтому accuracy там не подменяется предположением.

Запуск и доступ администратора: [backend/README.md](../../backend/README.md). Рабочие сервисы оставлены на localhost:3000; изменения не закоммичены.
