# Offline ablation — 20 сентября 2026

## Что проверялось

Проверен один и тот же набор из 42 фотографий на одной зафиксированной галерее каталога и на `google/siglip2-base-patch16-224`. В разбор вошли 32 изображения с рабочей разметкой: 22 полевых/сценовых и 10 студийных или рекламных. Ещё 10 файлов вынесены за скобки из-за неоднозначной разметки, повторов или рекламного кадра без однозначного товара. Рабочая разметка исправлена вручную только там, где исходный slug явно не соответствовал видимой этикетке; это не официальный конкурсный ground truth.

Галерея содержит 2 053 вина с первичной фотографией и 4 099 векторных записей full/crop. В 66 карточках первичная фотография отсутствует. Поиск в этом отчёте выполняется точным dot-product по сохранённой галерее; это не HTTP-прогон и не измерение полного SLA с PostgreSQL, сериализацией и UI.

## Основной результат

На наиболее полезном поднаборе из 22 сценовых фотографий лучший устойчивый вариант — поиск по кропу этикетки с галереей `full + crop`. Он даёт 68,2% Top-1 и 81,8% Top-5 по рабочей разметке. Для всех 32 размеченных файлов — 62,5% и 78,1% соответственно.

Это измерение показывает направление улучшений и потолок текущего пайплайна на сложных кадрах; его нельзя выдавать за финальную конкурсную accuracy, пока не будет независимой официальной разметки.

## Кроп и варианты изображения

| Вариант | Top-1, 22 scene | Top-5, 22 scene | Median latency | Вывод |
|---|---:|---:|---:|---|
| `full → full` | 50,0% | 77,3% | 112 ms | Фон и композиция мешают точному slug |
| `full → full+crop` | 59,1% | 86,4% | 112 ms | Добавление crop-эталонов помогает даже без crop query |
| `label → full` | 45,5% | 72,7% | 578 ms | Чистый label query, но не та галерея |
| `label → crop` | 63,6% | 72,7% | 578 ms | Большой прирост Top-1, но ниже запас Top-5 |
| **`label → full+crop`** | **68,2%** | **81,8%** | **578 ms** | **Лучший устойчивый baseline** |
| `bbox → full+crop` | 68,2% | 77,3% | 572 ms | Почти как label, но чаще теряет Top-5 |
| `enhanced label → full+crop` | 68,2% | 81,8% | 583 ms | Результат не лучше обычного label |
| `gray label → full+crop` | 59,1% | 77,3% | 574 ms | Цветовая информация нужна |
| `full + label`, max | 59,1% | 72,7% | 674 ms | Max-фузия слишком агрессивно выбирает один вид |
| `full + label`, mean | 63,6% | 77,3% | 674 ms | Лучше max, но хуже простого label → full+crop |

Переход `label → full` к `label → full+crop` дал **+22,7 п.п. Top-1** на scene-поднаборе. Переход от full query к label query при одинаковой галерее дал **+9,1 п.п.** (`full → full+crop`: 59,1%; `label → full+crop`: 68,2%). Поэтому главный технический вывод — хранить и использовать два типа эталонов, а query в первую очередь строить по этикетке.

## Цвет

| Сравнение | Top-1 | Изменение выдачи | Практический вывод |
|---|---:|---:|---|
| Без цвета → цвет по crop, 22 scene | 68,2% → 68,2% | 1 перестановка из 22 | Прироста accuracy нет |
| Без цвета → цвет по full, 22 scene | 68,2% → 68,2% | 2 перестановки из 22 | Full цвет не надёжнее crop цвета |
| Без цвета → цвет, все 42 | 47,6% → 47,6% | 2 перестановки из 42 | Цвет меняет ranking, но не добавляет правильных Top-1 |

В текущем виде цветовой сигнал слишком слабый и грубый: он смог поменять кандидата, но ни разу не превратил ошибку в правильный ответ на размеченном scene-поднаборе. Оставлять его можно только как небольшой tie-breaker после визуального score; увеличивать его вес сейчас оснований нет.

## OCR

| Вариант | Top-1, 22 scene | Top-5, 22 scene | Median latency |
|---|---:|---:|---:|
| Без OCR | 68,2% | 81,8% | 578 ms |
| OCR по label, добавка к Top-8 | 68,2% | 81,8% | 792 ms |
| OCR по full | 68,2% | 81,8% | 851 ms |
| OCR по enhanced label | 68,2% | 81,8% | 811 ms |
| OCR только как поиск по тексту | не пригоден | не пригоден | 696–1 008 ms |

OCR успешно отработал технически на 42/42 файлах, но при текущей добавке `+0,04` не изменил ни одного результата на scene-поднаборе. Он добавляет примерно 210–270 ms к тёплой локальной обработке. Самостоятельный OCR-поиск часто возвращает сорт или похожее слово вместо конкретной карточки. Его стоит включать условно: только при малом margin, только для близких кандидатов и только по различающим словам (год, reserve, special line, категория), а не как независимый retriever.

## Visual lock и preprocessing

| Изменение | Top-1, 22 scene | Результат |
|---|---:|---|
| `label_both` без lock | 68,2% | базовый лучший вариант |
| `label_both` с lock | 68,2% | на scene точность не выросла |
| `enhanced label` | 68,2% | enhancement не дал прироста |
| grayscale | 59,1% | потеря цвета ухудшает результат на 9,1 п.п. |

Lock переставил один ответ на scene-поднаборе, но не изменил accuracy. В текущей реализации нужно следить, чтобы финальный порядок, финальный score и признаки, по которым вычисляется confidence, были согласованы. Само увеличение margin не означает улучшение распознавания.

## Что это означает для плана и конкурса

| Зона | Что уже есть | Что осталось довести |
|---|---|---|
| Поиск | SigLIP2, full/crop галерея, pgvector, OCR/цветовые сигналы | Зафиксировать baseline `label → full+crop`, добавить независимые 200–300 полевых кадров и exact-slug метрики |
| Качество данных | 2 053 карточки с первичным фото из 2 119 slug | Проверить 66 пропусков, удалить или связать дубли, разделить варианты одной линейки и годы |
| Точность | Рабочий ablation Top-1 62,5% на 32 файлах | Пройти близкие этикетки, неизвестные вина, блики и наклон; отдельно считать Top-1, Top-5, F1 и отказ |
| OCR | Работает, но сейчас не даёт lift | Включать только для low-margin Top-K и измерять прирост exact slug, а не score |
| Уверенность | Есть margin/family logic | Убрать `family_tie` как достаточное основание exact match; калибровать `matched / uncertain / unknown` |
| Скорость | Локальный crop baseline около 0,58 с на CPU в этом офлайн-прогоне | Проверить текущий API cold/warm median и p95; отдельно время до карточки в браузере |
| UX | Карточка и новый визуальный блок готовы к проверке | Развести «не уверен» и «вина нет в каталоге», проверить camera flow и реальные ошибки |
| Презентация | Есть демонстрационный сценарий | Показать две похожие бутылки, неизвестное вино, объяснение уверенности и таблицу с числом тестов |

## Решение

1. Зафиксировать в продукте `label query + full/crop gallery` как baseline.
2. Не тратить ближайший цикл на увеличение веса цвета и полный OCR: эксперимент не показал прироста.
3. Направить следующий цикл на качество ground truth, near-duplicate/lineage disambiguation и калибровку отказа. Именно они сейчас ограничивают шанс получить конкурсные 50 баллов за достоверность.
4. После этого прогнать полный endpoint с той же разметкой и записать median/p95. Офлайн-цифры выше нельзя подменять SLA сервера.

Полный массив результатов: `results.json`; описание запуска и хеши версий: `run.json`; рабочая разметка: `manifest.json`.
