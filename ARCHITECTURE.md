# Сканер «Своё Вино» — решение, архитектура, запуск, API

Команда «Лунная призма», ЛЦТ-2026, задача Бизнес №10.
Демо: https://89.169.183.250.sslip.io/scanner · Код: https://github.com/bursinru/skanervina

## 1. Коротко о решении

Покупатель наводит камеру на бутылку — сервис находит этикетку, определяет вино в каталоге «Своё Вино» и сразу открывает **одну** карточку: рейтинг, вкус, сорт, регион, блюда, похожие вина и цифровой сомелье. Если уверенности нет, честно говорим «похоже на…» или «не знаем», а не подсовываем случайную карточку.

Распознавание устроено в два канала, которые работают параллельно:

- **картинка** — SigLIP 2 сравнивает кроп этикетки и весь кадр с фото и кропами каталога (pgvector);
- **текст этикетки** — PP-OCRv5 читает надписи на кадре, а они сверяются с карточками каталога и с текстом, заранее прочитанным с эталонных фото.

Итог выбирает обученная модель (softmax по кандидатам). Текст решает главную проблему визуального поиска: вина одной серии с почти одинаковой этикеткой, которые отличаются только сортом.

**Результат:** 77,1% верных Top-1 на 205 размеченных фото (было 65,9%); карточка «найдено» верна в 87 случаях из 88; медиана ответа на сервере 3,8 с. Работает на CPU, без GPU и без платных API.

## 2. Стек

| Слой | Технологии |
|---|---|
| Интерфейс | Статическая mobile-first вёрстка (`public/`), камера и галерея в браузере |
| Шлюз | Nuxt 4 / Nitro (`gateway/`), порт 3000, единый origin, проксирует только разрешённые маршруты |
| API | Python 3.11, FastAPI + Uvicorn (`backend/app/`), порт 8080, наружу не публикуется |
| Визуальный поиск | SigLIP 2 `google/siglip2-base-patch16-224` и `-384` (PyTorch, CPU), векторы 768 |
| Индекс и данные | PostgreSQL 17 + pgvector (HNSW, cosine), карточки в JSONB, анонимные профили |
| Текст этикетки | PP-OCRv5 mobile через RapidOCR + ONNX Runtime (кириллица и латиница) |
| Выбор ответа | Conditional logit по кандидатам на NumPy (`fusion.py`, веса `fusion.json`) |
| Детекция этикетки | Собственный детектор на OpenCV/NumPy (`label_detection.py`) |
| Выбор бутылки (опционально) | RT-DETR `PekingU/rtdetr_r18vd`, по умолчанию выключен (§8) |
| Развёртывание | Docker Compose (`db`, `recognition`, `web`), Nginx/Caddy с HTTPS перед портом 3000 |
| Сервер | Yandex Cloud, 4 vCPU Intel Ice Lake, 8 ГБ RAM, без GPU |

## 3. Как это работает

```text
фото ─► EXIF-поворот, прозрачный фон → белый
     ─► детектор этикетки: светлая бумага, цветные панели, границы; блики стекла отсекаются
     ─► кроп с запасом (ненадёжная форма → шире или всё фото)
     ├─► SigLIP 2: кроп (224) + кадр (224, 384) ─► pgvector ─► визуальный top-20
     └─► PP-OCRv5: кадр до 1280 px ─► слова с весами ─► текстовый top-10 (карточки и фото каталога)
                                   │
          кандидаты = визуальный top-20 ∪ текстовые top-10 (для них визуальный балл досчитывается точно)
                                   │
          модель выбора: 14 признаков ─► вероятности ─► правило «сорт на этикетке» для одной винодельни
                                   │
          карточка (≥ 80% или ≥ 60% с отрывом по картинке) · «похожие» (≥ 35% или сходство ≥ 65%) · «не знаем»
```

**Подготовка и кроп.** Поворот по EXIF, альфа-канал на белый фон, поиск центральной панели этикетки с защитным отступом (`label_detection.py`). Для каталога те же кропы нарезаются по студийным снимкам при импорте, так что сравниваются одинаковые виды.

**Визуальный поиск** (`vision.py`). Модель 224 кодирует кроп и кадр, модель 384 — кадр (мелкий текст этикетки различим лучше). Балл вина — среднее лучших оценок двух моделей по его фото и кропам.

**Текст этикетки** (`label_text.py`, `pp_ocr.py`). PP-OCR читает кадр, уменьшенный до 1280 px. Кроп отдельно не читаем: на 205 фото один кадр дал столько же верных ответов, сколько кадр + кроп, а работы вдвое меньше. Слова взвешиваются по уверенности, размеру шрифта и близости к центру кадра — текст соседних бутылок у краёв весит меньше. Сопоставление по IDF в двух индексах: поля карточки (название, винодельня, сорт, slug, категория) и текст с эталонного фото каждого вина (`catalog_photo_text.json`). Исправляются типичные ошибки OCR:
- латинские и греческие буквы вместо кириллицы (`KPACHOCTOP` → «Красностоп»);
- сорта латиницей (`RKATSITELI` ↔ «Ркацители», `PINOT MEUNIER`);
- опечатки в 1–2 буквы, склеенные слова (`ПИНОНУАР`), `2о24` → 2024.

Сладость, цвет и год сравниваются отдельными признаками: они одинаковы у всей серии, а в каталоге иногда записаны неточно.

**Модель выбора** (`fusion.py`). Softmax по кандидатам. Признаки: разрыв с визуальным лидером, текстовый балл и покрытие карточки, согласие по сладости, цвету и году, текст эталонного фото и др. Веса обучаются на размеченных фото (`backend/training/fit_fusion.py`). Поверх — правило для вин одной винодельни: если сорт или название на этикетке объясняет только близкий визуально соседний SKU, он становится первым.

**Что показываем.** Карточка — если выполнено любое из условий:
- вероятность Top-1 ≥ 0,8;
- вероятность ≥ 0,6 и по картинке вино опережает всех остальных кандидатов хотя бы на 0,06;
- вероятность ≥ 0,5 и отрыв от второго места ≥ 0,1;
- вероятность ≥ 0,4, по тексту этикетки вино опережает всех остальных хотя бы на 25%, и на этикетке найдено не меньше 20% его названия из каталога (например, «МУСКАТЕЛЬ … БЕЛЫЙ», когда фото в каталоге отличается от этикетки на полке).

На кросс-валидации карточку получают 49% фото, из них верны 95,5%. «Похожие» — если вероятность ≥ 0,35 или визуальное сходство ≥ 0,65. Иначе «не знаем» с похожими винами и цифровым сомелье.

**После распознавания.** Российские аналоги других виноделен (цвет, сладость, сорта, регион, сходство этикетки), цифровой сомелье за 3 шага (повод → блюдо → вкус), сравнение до трёх вин, избранное и собственные оценки. Всё строится из полей каталога, без внешнего LLM. Фото пользователей не сохраняются.

## 4. Точность и скорость

205 размеченных фото, Top-1 через `POST /v1/eval/predict` рабочего сервера (29.09.2026):

| Набор | Фото | Только картинка + Tesseract | Картинка + текст + модель |
|---|---:|---:|---:|
| Снимки у полки (телефон) | 65 | 53 | **55** |
| Живые фото из интернета | 42 | 21 | **32** |
| Каталожные фото из интернета | 98 | 61 | **71** |
| **Всего** | 205 | 135 (65,9%) | **158 (77,1%)** |

Веса модели обучены на этих же фото, поэтому честная оценка — кросс-валидация: 155–156 из 205 (≈ 76%). Оставшиеся ошибки — в основном почти одинаковые карточки одного вина в каталоге (разные slug одной бутылки) и этикетки, на которых OCR ничего не прочитал.

| Время ответа, 205 фото | Медиана | 95% фото быстрее |
|---|---:|---:|
| Внутри сервера | 3,8 с | 5,2 с |
| Через API, с сетью | 4,6 с | 6,6 с |

Главное ускорение — чтение текста только с кадра, уменьшенного до 1280 px, и 2 потока для PP-OCR, чтобы он не отнимал ядра у SigLIP: медиана 5,8 → 3,8 с. Нагрузка: 1000 сканов в сутки ≈ 65 минут работы одной ВМ; одновременно обрабатываются 2 запроса.

## 5. API

Публично доступен через Nuxt на порту 3000 (`/v1/*`). Фото — multipart-поле `image`: JPG, PNG, WebP, HEIC/HEIF, AVIF, до 15 МиБ.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/v1/eval/predict` | Конкурсный endpoint: всегда Top-1 `{"slug": "..."}`, в том числе при `uncertain` |
| `POST` | `/v1/recognize` | Распознавание для интерфейса: `status` (`matched` / `uncertain` / `unknown`), `confidence`, карточка `wine`, `lookalikes`, `alternatives`, `ranking.top5`; необязательное поле `bottle_box` — выбранная пользователем бутылка |
| `POST` | `/v1/bottles` | Бутылки в кадре с рамками (для ручного выбора) |
| `GET` | `/v1/catalog/{slug}` | Карточка вина |
| `GET` | `/v1/catalog/{slug}/alternatives` | Российские аналоги других виноделен с объяснением |
| `POST` | `/v1/sommelier` | Цифровой сомелье: повод, блюдо, вкус → вина каталога |
| `GET` | `/v1/search?q=...` | Текстовый поиск по каталогу, до 20 кандидатов |
| `GET` / `PUT` | `/v1/profile` | Избранное и оценки анонимного профиля (cookie HttpOnly, SameSite=Strict; `PUT` требует `X-Scanner-Client: web`) |
| `GET` | `/v1/scans/recent` | Последние сканы профиля |
| `GET` | `/healthz`, `/readyz` | Состояние: каталог, база, модели, OCR, число векторов в индексе |

Пример:

```sh
curl -F image=@bottle.jpg https://89.169.183.250.sslip.io/v1/eval/predict
# {"slug":"loco-cimbali-oranzh-muskat-oranzhevoe-suhoe-127"}
```

Диагностика: `/scanner?debug=1` (заголовок `X-Scanner-Debug: 1`) показывает вероятность, визуальное сходство, прочитанный текст, совпавшие слова, top-5 и время этапов. Режимы `image_*` / `ocr_*` через `X-Scanner-Mode` — только с `X-Scanner-Admin: $SCANNER_ADMIN_TOKEN`.

## 6. Запуск

### Одной командой (для организаторов)

Нужны Docker Desktop (или Docker Engine с Compose) и Node.js 20+. Каталог в Git не входит: положите в `Датасет/` таблицу `strapi_output0709_enriched.csv` и фото в `prod-svoe-vino-strapi/prod-svoe-vino/strapi/uploads`.

```sh
npm run organizer:setup   # проверка, .env со случайными секретами, сборка, импорт, запуск
# http://127.0.0.1:3000/scanner
npm run organizer:start | organizer:status | organizer:logs | organizer:stop
```

Первый запуск скачивает веса моделей (несколько ГБ). GPU не нужен.

### Сервер Linux (Docker Compose)

```sh
echo "POSTGRES_PASSWORD=$(openssl rand -hex 32)" > .env   # при HTTPS добавьте COOKIE_SECURE=true
docker compose build
docker compose up -d db
docker compose run --rm recognition python -m app.import_catalog \
  --catalog /catalog/strapi_output0709_enriched.csv --index \
  --images /catalog/prod-svoe-vino-strapi/prod-svoe-vino/strapi/uploads
docker compose up -d
curl http://127.0.0.1:3000/healthz
```

Перед портом 3000 — Nginx/Caddy с HTTPS (камере телефона нужен HTTPS), пример в `deploy/nginx.conf.example`. Импорт повторяемый: карточки обновляются по slug, фото переиндексируются только при изменении. `Датасет/extra-labels/<slug>/*.jpg` подключается автоматически. После смены детектора этикеток — импорт с `--force-crops`.

**Обновление кода распознавания.** `backend/app` смонтирован в контейнер, поэтому достаточно обновить файлы и выполнить `docker compose restart recognition`.

**Резервная копия.** `docker compose exec -T db pg_dump -U scanner -d scanner -Fc > scanner.dump`; `docker compose down -v` удаляет данные.

### Проверки

```sh
npm run test:backend     # unittest backend
npm run build:server     # сборка Nuxt
```

### Переобучение модели выбора

Нужны размеченные фото (`path`, правильный slug). Внутри контейнера выгружаются строки PP-OCR по каждому фото, визуальные баллы всех вин и OCR эталонных фото каталога. Затем:

```sh
python backend/training/fit_fusion.py --data <папка с выгрузкой> --write
```

Скрипт печатает leave-set-out и 5-fold кросс-валидацию и калибровку порога, затем записывает `backend/app/fusion.json` и `catalog_photo_text.json`.

## 7. Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CV_ENABLED` | `true` в Compose | Визуальный поиск |
| `CV_FUSION` | `true` | Картинка + текст + модель; `false` — прежний каскад SigLIP + Tesseract |
| `CV_FUSION_MATCH` | `0.8` | Порог вероятности для карточки (0,7 → карточка на 52% фото при точности ≈ 92%) |
| `CV_FUSION_LEAD_MATCH`, `CV_FUSION_VISUAL_LEAD` | `0.6`, `0.06` | Карточка и при меньшей вероятности, если есть явный отрыв по картинке |
| `CV_FUSION_SHARE_MATCH`, `CV_FUSION_SHARE_GAP` | `0.5`, `0.1` | Карточка, если у лидера большинство и заметный отрыв от второго |
| `CV_FUSION_TEXT_MATCH`, `CV_FUSION_TEXT_LEAD`, `CV_FUSION_TEXT_COVERAGE` | `0.4`, `0.25`, `0.2` | Карточка, если вино явно лидирует по тексту этикетки |
| `CV_OCR_FRAME_SIDE` | `1280` | Длинная сторона кадра для чтения текста |
| `CV_OCR_THREADS` | `2` | Потоки PP-OCR, чтобы не отнимать ядра у SigLIP |
| `CV_BOTTLE_AUTO` | `false` | Автоматически обрезать фото по найденной бутылке и показывать выбор бутылки в интерфейсе |
| `CV_SECONDARY_MODEL` | `true` | Второй энкодер SigLIP 384 |
| `CV_DEVICE`, `CV_THREADS` | `cpu`, `4` | Устройство и потоки PyTorch |
| `SCANNER_ADMIN_TOKEN` | — | Доступ к диагностическим режимам |

## 8. Ограничения и планы

- **Выбор бутылки перед поиском** выключен: на 107 снимках у полки и живых фото он помог на 7, навредил на 12 и добавил ~0,6 с. Модель выбора обучалась без него; после дообучения на кропах бутылок стоит проверить снова.
- **Лёгкие фото** — на ~20% фото картинка уверена и соседей по серии нет; там чтение текста можно пропускать без потери точности (ещё −0,5–1 с).
- **Дубли в каталоге** — несколько slug одной бутылки неразличимы ни по фото, ни по тексту; нужна чистка каталога.
- **Данные** — пополнение индекса и дообучение модели выбора на реальных фото пользователей; распознавание вин вне каталога и российские аналоги к ним.
- **Скорость** — ONNX и квантование SigLIP, GPU при росте нагрузки.
- **Продукт** — мобильные приложения iOS и Android, встраивание `/scanner` в vino-svoe.ru, персональные рекомендации по оценкам.
