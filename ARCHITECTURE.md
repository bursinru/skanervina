# Архитектура сканера «Своё Вино»

## Слои

1. **Интерфейс** — статическая вёрстка в стиле портала (`public/`) за единым origin Nuxt/Nitro (`gateway/`, порт 3000). Камера и галерея отправляют JPEG/PNG/WebP на `/v1/recognize`.
2. **Нормализация фото** — EXIF-поворот, поиск центральной панели этикетки, crop с запасом. Enhancement считается только в debug-режимах `*_enhanced`.
3. **Признаки** — SigLIP 2 224 (кроп этикетки + кадр) и 384 (кадр) на CPU, векторы 768 измерений. Параллельно PP-OCRv5 (кириллица + латиница) читает кроп этикетки и кадр.
4. **Поиск по каталогу** — PostgreSQL 17 + pgvector, cosine / HNSW. Индексируются только файлы карточек вин (sitemap + `svoe_vino_image_url`), не медиа статей.
5. **Текст этикетки** (`backend/app/label_text.py`) — слова PP-OCR взвешиваются по уверенности, размеру и близости к центру кадра (соседние бутылки у краёв). Сопоставление с каталогом по IDF в двух индексах: поля карточки (название, винодельня, сорт, slug, категория) и текст, заранее прочитанный PP-OCR с эталонного фото каждого вина (`catalog_photo_text.json`). Нормализация учитывает ошибки OCR: латинские и греческие двойники кириллицы (`KPACHOCTOP`), латинские названия сортов (`RKATSITELI` ↔ «Ркацители»), опечатки до 1–2 букв, склеенные слова, `2о24` → 2024. Сладость и цвет — отдельные признаки, не часть текстового балла.
6. **Слияние** (`backend/app/fusion.py`) — кандидаты: визуальный top-20 ∪ текстовый top-10 обоих индексов, для текстовых кандидатов визуальный балл досчитывается точно. Softmax (conditional logit) по 14 признакам: визуальный разрыв с лидером, текстовый балл и покрытие, согласие по сладости/цвету/году, текст эталонного фото. Веса — `fusion.json`, обучаются `backend/training/fit_fusion.py` на размеченных фото. Поверх — правило для одной винодельни: если сорт или название на этикетке объясняет только близкий визуально соседний SKU, он становится первым. Без `fusion.json` или при `CV_FUSION=false` работает прежний каскад SigLIP + Tesseract.
7. **Выдача карточки** — `/v1/recognize` возвращает одну карточку при `matched` или `uncertain`. `unknown` не подменяет ответ похожей этикеткой. Метрики `ranking.f1_top1` / `ranking.f1_top5` и список top-5 есть в API (в UI только в `?debug=1`).
8. **Конкурсный endpoint** — `POST /v1/eval/predict` всегда отдаёт Top-1 `{"slug":"..."}` после слияния, в том числе при `uncertain`. Скрипт организатора не знает порог веба.
9. **После поиска** — российские аналоги других виноделен (`/v1/catalog/{slug}/alternatives`) и цифровой сомелье по ситуации (`POST /v1/sommelier`). Без внешнего LLM: правила по цвету, сортам и блюдам каталога.
10. **Профили** — анонимные cookie, сохранения и оценки в PostgreSQL.

## Пороги продукта (не скрипта)

- Слияние: `matched` при вероятности top-1 ≥ 0.8 (`match_probability` в `fusion.json`, переопределяется `CV_FUSION_MATCH`); на кросс-валидации такие ответы верны в 97%. Ниже — `uncertain`, если вероятность ≥ 0.35 или визуальное сходство ≥ 0.65, иначе `unknown`.
- Прежний каскад: `CV_MATCH_THRESHOLD=0.75`, `CV_MATCH_MARGIN=0.04` — `matched`; ниже, но ≥ 0.65 — `uncertain`.
- F1 в API без ground truth: гармоническое среднее similarity top-1 и нормированного отрыва до k-го соседа (шкала 0.15).

## Точность

205 размеченных фото (65 снимков у полки, 140 фото этикеток из интернета), Top-1 через `/v1/eval/predict` на рабочем сервере:

| Набор | Фото | Каскад SigLIP + Tesseract | SigLIP + PP-OCR + слияние |
|---|---:|---:|---:|
| Снимки у полки | 65 | 53 | 55 |
| Живые фото из интернета | 42 | 21 | 29 |
| Каталожные фото из интернета | 98 | 61 | 73 |
| **Всего** | 205 | 135 (65,9%) | **157 (76,6%)** |

Веса обучены на тех же 205 фото, поэтому честная оценка — кросс-валидация: 155–156 из 205 (≈76%). Медиана ответа 6,1 с, p95 11 с (4 vCPU). Остаток ошибок — в основном почти одинаковые карточки одного вина в каталоге и этикетки, на которых OCR ничего не прочитал.

Переобучение: выгрузить признаки на сервере (PP-OCR строк, визуальные баллы всех вин, OCR эталонов) и запустить `python backend/training/fit_fusion.py --data <папка> --write` — он печатает leave-set-out и 5-fold CV и записывает `fusion.json` и `catalog_photo_text.json`.

## Запуск

Docker Compose из корня репозитория: `db` → импорт CSV и индекс → `recognition` + `web`. Публичный порт 80 через Nginx на `127.0.0.1:3000`. Подробности: [backend/README.md](backend/README.md).
