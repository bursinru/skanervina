# Архитектура сканера «Своё Вино»

## Слои

1. **Интерфейс** — статическая вёрстка в стиле портала (`public/`) за единым origin Nuxt/Nitro (`gateway/`, порт 3000). Камера и галерея отправляют JPEG/PNG/WebP на `/v1/recognize`.
2. **Нормализация фото** — EXIF-поворот, поиск центральной панели этикетки, crop с запасом. Enhancement считается только в debug-режимах `*_enhanced`.
3. **Признаки** — SigLIP 2 `google/siglip2-base-patch16-224` на CPU (или `CV_DEVICE`). Вектор 768 измерений. OCR Tesseract по умолчанию выключен (`CV_OCR_ENABLED=false`): в ТЗ он опционален и замедляет ответ.
4. **Поиск по каталогу** — PostgreSQL 17 + pgvector, cosine / HNSW. Одна эталонная фотография на slug. Индексируются только файлы карточек вин (sitemap + `svoe_vino_image_url`), не медиа статей.
5. **Выдача карточки** — `/v1/recognize` возвращает одну карточку при `matched` или `uncertain`. `unknown` не подменяет ответ похожей этикеткой. Метрики `ranking.f1_top1` / `ranking.f1_top5` и список top-5 есть в API (в UI только в `?debug=1`).
6. **Конкурсный endpoint** — `POST /v1/eval/predict` всегда отдаёт Top-1 `{"slug":"..."}` из визуального поиска, в том числе при `uncertain`. Скрипт организатора не знает порог веба.
7. **После поиска** — российские аналоги других виноделен (`/v1/catalog/{slug}/alternatives`) и цифровой сомелье по ситуации (`POST /v1/sommelier`). Без внешнего LLM: правила по цвету, сортам и блюдам каталога.
8. **Профили** — анонимные cookie, сохранения и оценки в PostgreSQL.

## Пороги продукта (не скрипта)

- `CV_MATCH_THRESHOLD=0.75`, `CV_MATCH_MARGIN=0.04` — статус `matched` для веба.
- Ниже, но ≥ 0.65 — `uncertain`: карточка с предупреждением.
- F1 в API без ground truth: гармоническое среднее similarity top-1 и нормированного отрыва до k-го соседа (шкала 0.15).

## Запуск

Docker Compose из корня репозитория: `db` → импорт CSV и индекс → `recognition` + `web`. Публичный порт 80 через Nginx на `127.0.0.1:3000`. Подробности: [backend/README.md](backend/README.md).
